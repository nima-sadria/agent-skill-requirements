سند توجیهی جامع: بررسی معماری، ویژگی‌ها و قابلیت‌های فنی پنل 3X-UI (نسخه v3.10.0) و زیست‌بوم Xray-core  
خلاصه مدیریتی  
توسعه سیستم‌های دورزدن سانسور و مدیریت پروکسی‌های شبکه‌ای وارد فاز جدیدی از پیچیدگی شده است که ناشی از به‌کارگیری تکنیک‌های پیشرفته بازرسی عمیق بسته‌ها (DPI) و پروب فعال (Active Probing) توسط فیلترینگ‌های دولتی است. پروژه open-source 3X-UI به عنوان یک پنل مدیریتی تحت وب برای هسته Xray-core، در نسخه v3.10.0 به یک نقطه عطف معماری و عملیاتی دست یافته است. این نسخه با معرفی مکانیزم‌های انتقال جدید، سخت‌سازی امنیتی در سطح سیستم‌عامل، و همگام‌سازی حالت‌مند بین نودها، بازدهی و امنیت سیستم را به میزان چشمگیری افزایش داده است.  
دستاوردهای کلیدی نسخه v3.10.0

* مکانیزم‌های انتقال نسل جدید: معرفی پروتکل XDRIVE (انتقال ناهمگام و غیرمستقیم داده‌ها از طریق APIهای ذخیره‌سازی ابری مانند Google Drive جهت نابودی امضای ترافیک) و پروتکل MASQUE (تونل‌سازی QUIC/HTTP3 با قابلیت کپسوله‌سازی Cloudflare WARP).  
* ارتقا به Xray-core v26.10.10: پشتیبانی از اسکریپت‌نویسی dynamic Lua برای DNS و routing، ارتقای رابط TUN با مسدودسازی فیلترینگ DNS در ویندوز (WFP) و systemd-resolved در لینوکس، و تغییر رفتار پیش‌فرض اعتبارسنجی TLS به گواهی‌های ریشه داخلی Mozilla.  
* بازسازی همگام‌سازی نودها (Stateful Reconciliation): اعمال تغییرات کاربری در لحظه (In-place updates) بدون بازسازی Listener و قطعی اتصال سایر کاربران، اصلاح تداخلات دیتابیس و مکانیزم‌های خودترمیم نودهای وابسته.  
* ارتقای امنیت سیستم (Sandboxing): محدودسازی فرآیند Panel تحت خدمت unit فایل‌های systemd با دسترسی صرفاً خواندنی به مسیرهای اصلی ریشه، اعمال UMask=0077 و فیلترهای Seccomp BPF جهت Neutralize ساختن اکسپلویت‌های اجرای کد از راه دور (RCE).  
* مهاجرت رمزنگاری: حذف سایفر منسوخ 2022-blake3-chacha20-poly1305 در Shadowsocks-2022 و انتقال خودکار آن به 2022-blake3-aes-256-gcm.  
* معماری جامع API و اتوماسیون: ارائه API کامل بر پایه OpenAPI 3 با پشتیبانی از احراز هویت Bearer Token و Cookie، قابلیت‌های مدیریت گروهی (Bulk Operations)، پیش‌نمایش تمدید خودکار و ارتباطات real-time از طریق WebSocket.

۱. چشم‌انداز تهدیدات و ضرورت‌های معماری  
تغییر الگوی سانسور اینترنت از تشخیص امضای اتوماتیک پروتکل‌ها به سمت عملیات ترکیبی هوش مصنوعی و پروب فعال انسانی (Manual Infiltration)، پروکسی‌های مدرن را مجبور به شبیه‌سازی دقیق ترافیک‌های معتبر کرده است. در این الگوی جدید، بازرسان سانسور با خرید اشتراک از ارائه‌دهندگان، دامنه و IP نودها را استخراج کرده و با ارسال درخواست‌های پروب فرکانس بالا، نودها را شناسایی و مسدود می‌کنند. پاسخ جامعه توسعه‌دهندگان، اتخاذ استانداردهایی نظیر AnyTLS و REALITY بوده است. با این حال، فیلترینگ‌های منطقه‌ای با به‌کارگیری لیست‌های سفید TLS SNI (TLS SNI Whitelisting)، اتصالات خارج از لیست مجاز را مسدود می‌کنند. پنل 3X-UI برای مقابله با این تهدیدات توسعه یافته است.  
ساختار و سازگاری زیست‌بوم 3X-UI  
کدبیس پنل 3X-UI عمدتاً از Go (%۶۰.۸) برای کارایی بالا و امنیت حافظه، و TypeScript (%۳۴.۸) برای رابط کاربری فرانت‌اند تشکیل شده است. این پنل به صورت Progressive Web Application (PWA) قابل نصب است.

| مولفه | مشخصات و گزینه‌ها |
| :---: | :---: |
| معماری‌های مورد پشتیبانی | amd64, 386, arm64 (aarch64), armv7, armv6, armv5, s390x |
| محیط‌های استقرار | Bare Metal, VMs, Docker Containers, Cloud-init, Terraform (terraform-provider-3x-ui) |
| پایگاه‌های داده | SQLite (پیش‌فرض embedded)، PostgreSQL 18 (محلی یا ریموت) |
| ابزارهای مدیریتی و هشدار | برنامه‌ کاربردی 3X-UI Manager (اندروید در F-Droid)، ربات‌های تلگرام و دیسکورد |

۲. مکانیزم‌های انتقال نسل جدید و دورزدن سانسور  
پروتکل XDRIVE: انتقال ناهمگام از طریق ابر (Cloud-Decoy Transport)  
پروتکل XDRIVE مفهوم سوکت‌های متصل و دائم‌الانتقال را کنار می‌گذارد. جریان‌های پروکسی (مانند VLESS یا Trojan) به فایل‌های گسسته و رمزنگاری‌شده تبدیل شده و از طریق APIهای HTTP یا سرویس‌های ذخیره‌سازی ابری (مانند Google Drive) رد و بدل می‌شوند.  
مسیر جریان داده:

```
[Client] ---> (Encrypted Chunk File) ---> [Cloud Storage API / Google Drive] ---> (Fetch Chunk) ---> [3X-UI / Xray Node]
```

* نابودی امضا (Signature Annihilation): موتور DPI فقط درخواست‌های استاندارد HTTPS را به سمت APIهای معتبر بین‌المللی مشاهده می‌کند. مسدودسازی این IPها موجب آسیب جانبی شدید به اقتصاد دیجیتال کشور سانسورکننده می‌شود.  
* اختلال در تحلیل زمانی (Temporal Disruption): الگوی داده‌ها به صورت انفجاری (Bursty) و مشابه آپلود/دانلود فایل جلوه می‌کند، که الگوریتم‌های زمان‌بندی فیلترشکن‌یاب را مختل می‌سازد.  
* تایید اعتبار پیشگیرانه: پنل 3X-UI پیکربندی‌های غیرقابل اجرا در Xray-core را پیش از ذخیره‌سازی شناسایی و رد می‌کند تا از Core Panic جلوگیری شود.

پروتکل MASQUE (Multiplexed Application Substrate over QUIC Encryption)  
MASQUE امکان تونل‌سازی بسته‌های IP یا UDP را در قالب اتصالات HTTP/3 (QUIC) یا HTTP/2 فراهم می‌سازد:

* احراز هویت کاربر: مشتریان MASQUE از طریق ایمیل و کلمه عبور اختصاصی احراز هویت می‌شوند و لینک‌های اشتراک JSON آن‌ها به طور اتوماتیک تولید می‌گردد.  
* کپسوله‌سازی WARP (WARP-MASQUE): ثبت دستگاه‌های Cloudflare WARP بر روی MASQUE (ساخت اکسپورت warp-masque) اجازه می‌دهد ترافیک WireGuard که دسترسی مستقیم UDP آن توسط ISPها مسدود شده، در قالب اتصالات HTTP/3 منتقل شود.  
* محدودیت‌های فرمت لینک: به دلیل پیچیدگی پارامترها، لینک‌های متنی معمولی (URI) و کلاینت‌هایی مانند Clash قادر به کپسوله‌سازی MASQUE نیستند و این پیکربندی‌ها از لینک‌های متنی ساده صرف‌نظر می‌کنند.

پروتکل REALITY و XTLS-Vision  
پروتکل REALITY با حذف گواهی‌های TLS سمت سرور و استفاده از گواهی‌های واقعی سایت‌های هدف (Target Sites)، ویژگی‌های TLS Fingerprint سرور را به کلی نابود می‌کند.

```json
// نمونه پیکربندی Inbound برای VLESS-REALITY
{
  "listen": "0.0.0.0",
  "port": 443,
  "protocol": "vless",
  "settings": {
    "clients": [
      {
        "id": "YOUR_UUID",
        "flow": "xtls-rprx-vision"
      }
    ],
    "decryption": "none"
  },
  "streamSettings": {
    "network": "raw",
    "security": "reality",
    "realitySettings": {
      "show": false,
      "target": "example.com:443",
      "xver": 0,
      "serverNames": ["example.com", "www.example.com"],
      "privateKey": "YOUR_PRIVATE_KEY",
      "shortIds": ["", "0123456789abcdef"],
      "mldsa65Seed": ""
    }
  }
}
```

* الزامات سایت هدف: سایت باید خارجی بوده، از TLS v1.3 و HTTP/2 پشتیبانی کند و دامنه آن برای ریدرکت استفاده نشده باشد.  
* پشتیبانی از الگوریتم‌های پساکوانتومی: قابلیت تولید و اعتبارسنجی کلیدهای ML-DSA-65 و ML-KEM-768 جهت امضا و تایید گواهی‌ها در برابر تهدیدات رایانش کوانتومی.

۳. تکامل هسته مسیریابی Xray-core v26.10.10 و پروتکل‌ها  
اسکریپت‌نویسی Lua در DNS و مسیریابی  
ارتقا به Xray-core v26.10.10 امکان برنامه‌نویسی پویای مسیرها و وضوح نام‌ها را فراهم آورده است:

1. Lua DNS: تعریف منطق پویا برای تعویض Serverهای Upstream بر اساس شرایط شبکه یا هویت کلاینت.  
2. Lua Routing: با فعال‌سازی اسکریپت Lua در تنظیمات پایه پنل، تمامی قوانین ایستا (Static Rules) قبلی در رابط کاربری کنار گذاشته شده و مسیریابی به صورت کاملاً برنامه‌ریزی‌پذیر اجرا می‌شود.

امن‌سازی رابط TUN و Finalmask

* رابط TUN: قابلیت تعیین نوع آداپتور ویندوز جهت سازگاری با سیستم‌های مجازی‌سازی. جلوگیری از DNS Leak با تنظیم مستقیم systemd-resolved در لینوکس به سمت گیت‌وی TUN و استفاده از Windows Filtering Platform (WFP) در ویندوز.  
* موتور Finalmask: پشتیبانی از متغیرهای سفارشی هدر، تبدیلات ریاضی، گروه‌بندی خطاهای TCP، حالت‌های پریفیکس UDP و ماسک Sudoku UDP. حفظ دقیق بازه‌های نویز (Noise Reset Ranges) هنگام ذخیره پیکربندی.

تغییر رفتار گواهی‌های ریشه TLS  
Xray-core v26.10.10 به طور پیش‌فرض اتصالات TLS خروجی را فقط با گواهی‌های ریشه Mozilla داخلی خود اعتبارسنجی می‌کند و Store مربوط به سیستم‌عامل میزبان را ندید می‌گیرد. در محیط‌های سازمانی که نیاز به SSL Inspection داخلی دارند، باید گزینه Use system CA در تنظیمات Outbound TLS فعال گردد.  
پروتکل‌های TUIC v5 و AmneziaWG

* TUIC v5 بومی: اجرا به صورت کاملاً داخلی در پنل Go بدون نیاز به باینری‌های Sidecar. پشتیبانی از الگوریتم کنترل ازدحام BBR، حفظ IP مقصد اصلی و نمایش نرخ سرعت زنده کلاینت‌ها.  
* AmneziaWG: رفع مشکل شکستگی بسته‌ها (Fragmentation) با شکستن فعالانه بسته‌های پاسخ UDP در صورت تجاوز از MTU تونل. مدیریت صحیح کلیدهای عمومی و Keepalive کلاینت‌هایی که به طور همزمان روی WireGuard و AmneziaWG تعریف شده‌اند.

۴. همگام‌سازی ناوگان توزیع‌شده و بازسازی حالت‌مند  
در محیط‌های بزرگ که از مدل Master-Node (Hub and Spoke) استفاده می‌کنند، نسخه v3.10.0 تغییرات اساسی در منطق همگام‌سازی ایجاد کرده است.

```
         +-------------------+       
         |    Master Hub     |       
         +---------+---------+       
                   |                 
  +----------------+----------------+
  | (mTLS/Token)   | (mTLS/Token)   | (mTLS/Token)
  v                v                v
+--------------+ +--------------+ +--------------+
| Child Node 1 | | Child Node 2 | | Child Node 3 |
+--------------+ +--------------+ +--------------+
```

به‌روزرسانی کاربران در‌دست‌رس (Non-Disruptive In-Place Updates)  
در نسخه‌های قبلی، تمدید یا تغییر وضعیت یک کاربر باعث بازسازی کامل Inbound Listener می‌شد که به قطعی اتصال تمام کاربران آن پورت می‌انجامید.

* راهکار v3.10.0: تغییرات کاربر به صورت مستقیم در حافظه فعال (Active Memory) نگاشت می‌شود. Listener بدون تغییر باقی مانده و اتصالات سایر کاربران بر روی آن پورت قطع نمی‌شود.  
* تراکنش‌های دیتابیس: همگام‌سازی تراکنش‌ها مانع از اوررایت شدن اطلاعات کلاینت‌ها در ویرایش‌های همزمان (Microsecond Race Conditions) می‌شود.

مکانیزم‌های تاب‌آوری همگام‌سازی Master-Node

1. اختیارات مدیریتی مبتنی بر توکن: نودهای enrolled شده با توکن‌های اختصاصی یا mTLS دارای اختیارات کامل جهت ریست حجم، تنظیم مرتب‌سازی و خواندن Inboundها بدون دریافت خطای 403 Forbidden هستند.  
2. موتور خودترمیم (Self-Healing): در صورت حذف اشتباه یک Inbound در نود فرعی، حلقه همگام‌سازی Master عدم وجود آن را شناسایی کرده و مجدداً آن را بر روی نود ایجاد می‌کند.  
3. محافظت در برابر گزارش حالت خالی (Empty State Protection): اگر نودی در زمان بوت لیستی خالی از کلاینت‌ها ارسال کند، Master آن را فرآیند راه‌اندازی موقت تشخیص داده و لیست مرجع را به نود پوش می‌کند (مانع از پاک شدن دیتابیس اصلی می‌شود).  
4. رمزنگاری توکن نودها: با تنظیم NODE\_TOKEN\_ENCRYPTION=required کلیدهای فعال ۳۲ بایتی base64 در یک فایل keyring با دسترسی محدود (mode 0600\) ذخیره می‌شوند.

۵. امن‌سازی سیستم، ساندباکس و پایگاه داده  
ساندباکس در سطح systemd  
برای کاهش سطح حمله و جلوگیری از اکسپلویت‌هایی مانند CVE-2025-6703 (تزریق HTML از طریق استایل‌ها)، سرویس 3X-UI تحت یک محیط محدودشده اجرا می‌شود:

```
# نمونه ساختار امنیتی سرویس systemd
[Service]
ReadOnlyPaths=/usr /boot /etc /home /root
UMask=0077
ProtectKernelTunables=true
ProtectControlGroups=true
SystemCallFilter=@system-service
```

* مسیرهای فقط خواندنی: مسیرهای اصلی سیستم‌عامل به صورت Read-Only مونت می‌شوند.  
* ماسک دسترسی فایل‌ها (UMask=0077): تمام فایل‌ها و لوگ‌های جدید فقط توسط اکانت سرویس قابل خواندن و نوشتن هستند.  
* فیلتر Seccomp BPF: روی systemd نسخه ۲۳۹ به بالا، فراخوانی‌های غیرمرتبط سیستم‌عامل توسط kernel رد می‌شوند.  
* اعمال Override سفارشی: در صورت نیاز به دسترسی نوشتن Xray به مسیرهای خاص، تغییرات باید در فایل 20-local.conf اعمال شوند.

املیت زنجیره تامین و نصب

* گیت‌هاب اکشنز: سلب دسترسی‌های نوشتن و توکن‌های OIDC در workflows مربوط به Pull Requestها.  
* تایید SHA256: تایید اجباری هش فایل‌ها قبل از اجرا توسط اسکریپت‌های install.sh و update.sh.  
* نصب غیرتعاملی: با تنظیم متغیر XUI\_NONINTERACTIVE=1 نصب بدون پرسش انجام شده و نام کاربری، رمز عبور و مسیر پنل تصادفی در مسیر /etc/x-ui/install-result.env ذخیره می‌شود.

یکپارچگی پایگاه داده و نگهداری

* پشتیبانی از PostgreSQL 18: اتصال مستقیم به مخازن PGDG. ارتقای خودکار نسخه اصلی دیتابیس‌های فعال جهت جلوگیری از خرابی اسکیما ممنوع شده است.  
* مهاجرت‌های اتمی SQL: تضمین اجرای کامل SQL Schema Migrations پیش از استارت سرویس پنل جهت جلوگیری از خطاهای "duplicate column".  
* عدم تداخل SSL ACME: فرآیند آپدیت پنل دیگر اسکریپت acme.sh را اجرا نمی‌کند و تنظیمات SSL موجود دست‌نخورده باقی می‌مانند.

۶. معماری API، مدیریت کلاینت‌ها و تجربه کاربری  
قابلیت‌های API پنل (v3.x API)  
پنل دارای یک REST API کامل بر پایه مشخصه OpenAPI 3 (/panel/api/openapi.json) است:

* روش‌های احراز هویت: نشست وب (Session Cookie به همراه CSRF Token) یا توکن اختصاصی Bearer (تعریف‌شده در تنظیمات امنیتی).

```
[Client/Bot] ---> Bearer Token (Authorization: Bearer) ---> [/panel/api/*]
[Browser SPA] ---> Login (Cookie) + X-CSRF-Token ------------> [/panel/api/*]
```

اندپوینت‌های کلیدی API:

| اندپوینت | روش | توضیحات فنی |
| :---: | :---: | :---: |
| /panel/api/inbounds/list/slim | GET | دریافت لیست سبک Inboundها بدون دیتای سنگین کلاینت‌ها |
| /panel/api/clients/list/paged | GET | لیست کلاینت‌ها با قابلیت فیلتر، سورت و صفحه‌بندی سمت سرور |
| /panel/api/clients/add | POST | ساخت کلاینت جدید و اتچ همزمان به چندین Inbound |
| /panel/api/clients/bulkAdjust | POST | تغییر تاریخ انقضا و حجم گروهی از کلاینت‌ها |
| /panel/api/server/status | GET | دریافت وضعیت زنده پردازنده، رم، دیسک، ترافیک و Xray |
| /panel/api/xray/testOutbounds | POST | تست گروهی (تا ۵۰ عدد) Outboundها از نظر Latency و TTFB |

مدیریت پیشرفته کلاینت‌ها

* پارامترهای انقضا و تمدید خودکار: محاسبه دقیق تاریخ انقضا بر اساس بازه‌های روزانه، هفتگی یا تقویمی ماهانه. قابلیت پیش‌نمایش تمدید از طریق اندپوینت /panel/api/clients/renewalPreview.  
* محدودیت HWID: محدودسازی تعداد دستگاه‌های متصل با قابلیت استعلام وضعیت از طریق اندپوینت sub-server (/{subPath}{subid}/hwid-status).  
* لینک‌های Happ Crypt5: قابلیت تولید خودکار لینک‌های رمزنگاری‌شده Happ locally بدون ارسال اطلاعات به سرور ثالث.

همگام‌سازی سرور اشتراک (Subscription Server)  
سرور اشتراک به صورت مجزا روی پورت اختصاصی (پیش‌فرض ۲۰۹۶) قرار دارد:

* اصلاح فرمت JSON: خروجی مقدار "encryption": "none" در صورت عدم وجود کلید رمزنگاری برای VLESS جهت جلوگیری از Parse Error در کلاینت‌ها.  
* ارسال ECH و Certificate Pinning: انتشار پارامترهای Encrypted Client Hello و هش SHA-256 گواهی‌ها در خروجی JSON.  
* پشتیبانی از فرمت‌های متنوع: خروجی‌های Base64 متنی، JSON Array، و YAML سازگار با Clash/Mihomo.

رویدادهای زنده WebSocket (/ws)  
ارتباط websocket دوطرفه پیام‌هایی با ساختار { type, payload, time } ارسال می‌کند. انواع رویدادها عبارتند از: status, traffic, client\_stats, inbounds, outbounds, nodes, notification, xray\_state, invalidate.  
۷. استقرار پایدار و الگوهای پیکربندی بهینه  
برای دستیابی به بالاترین سطح امنیت و کارایی، ترکیب پنل 3X-UI با وب‌سرورهای قدرتمند نظیر Nginx یا Caddy توصیه می‌شود.  
مشخصات الگوهای بهینه استقرار

1. اتصال از طریق Unix Domain Socket (UDS): استفاده از UDS به جای پورت‌های TCP محلی جهت کاهش Overhead شبکه و حذف امکان اسکن پورت‌های داخلی. استفاده از حالت Abstract UDS در Caddy جهت عدم نیاز به تنظیمات دسترسی فایل.  
2. پشتیبانی از PROXY Protocol: انتقال IP واقعی کلاینت از وب‌سرور به Xray جهت اعمال دقیق محدودیت IP (IP Limit) و ثبت در Fail2ban.  
3. همزمانی HTTP/2 و HTTP/3 (QUIC): پیکربندی Caddy برای ارائه همزمان H2C و HTTP/3 روی پورت UDP 443 برای پروکسی‌های مبتنی بر XHTTP یا NaiveProxy.

```
            +-----------------------------------+            
            |         Internet Traffic          |            
            +---------+-----------------+-------+            
                      | TCP 443         | UDP 443 (QUIC/H3)  
                      v (TLS/H2)        v                    
            +-----------------------------------+            
            |           Nginx / Caddy           |            
            +-----------------+-----------------+            
                              | UDS / PROXY Protocol         
                              v                              
            +-----------------------------------+            
            |           3X-UI / Xray            |            
            +-----------------------------------+            
```

چک‌لیست الزامات امنیتی استقرار سرور

* باز بودن پورت‌های TCP/80 و TCP/443 و UDP/443 در فایروال سرور.  
* عدم اشغال پورت TCP/80 هنگام اخذ گواهی‌های Standalone SSL.  
* فعال‌سازی ابزار Fail2ban با قابلیت دسترسی به NET\_ADMIN و NET\_RAW در محیط‌های داکر.  
* تنظیم صحیح متغیرهای محیطی امنیتی سیستم‌عامل و به‌روزرسانی نودهای فرعی همزمان با سرور اصلی.

نتیجه‌گیری  
انتشار نسخه v3.10.0 پروژه 3X-UI، این پنل را از یک ابزار مدیریتی ساده به یک سیستم ارکستراسیون پروکسی سطح سازمانی و مقاوم در برابر سانسور تبدیل کرده است. تلفیق قابلیت‌های پیشرفته Xray-core v26.10.10، پروتکل‌های نوآورانه‌ای مانند XDRIVE و MASQUE، ساندباکس شدید در سطح Kernel/Systemd، و سیستم همگام‌سازی حالت‌مند نودها، زیرساختی قدرتمند، مقیاس‌پذیر و ایمن را برای عبور از پیچیده‌ترین مکانیزم‌های فیلترینگ فراهم می‌سازد.
